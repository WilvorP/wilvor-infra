This file documents the current manual workflow for:

1. SIGMET poller
2. SIGMET processor
3. SIGMET raw archive
4. ActiveHazards DynamoDB table
5. HazardCells DynamoDB table
6. Weather.changed EventBridge rule and CloudWatch target
7. METAR poller
8. METAR raw archive
9. METAR raw Kinesis stream

OpenSky and aircraft-related resources belong to a teammate and are not covered here.

Current implementation status
-----------------------------

SIGMET:
NOAA SIGMET API
-> SIGMET poller Lambda
-> SIGMET S3 archive bucket
-> sigmet-raw Kinesis stream
-> SIGMET processor Lambda
-> ActiveHazards DynamoDB table
-> HazardCells DynamoDB table
-> Weather.changed EventBridge event
-> CloudWatch Events log group

METAR:
NOAA METAR API
-> METAR poller Lambda
-> METAR S3 archive bucket
-> metar-raw Kinesis stream

METAR does not yet have a processor. Therefore, MetarLatest is expected to remain empty.

PART 2 - FORMAT, INITIALIZE, VALIDATE, AND PLAN
===============================================

From the repository root:

terraform fmt -recursive

Move into the development environment:

cd envs\dev

Initialize Terraform:

terraform init -reconfigure

Validate:

terraform validate

Expected:

Success! The configuration is valid.

Login to AWS:

$env:AWS_PROFILE="wilvor-dev"
$env:AWS_REGION="us-west-1"
aws sso login --profile wilvor-dev

Create a plan:

terraform plan

Expected characteristics:

- Weather resources appear under module.sigmet, module.metar, and module.weather_events.
- No SIGMET or METAR resources appear under module.aircraft_foundation.
- Separate aircraft, SIGMET, and METAR archive buckets appear.
- sigmet-clean and metar-clean do not appear.
- Schedules are disabled in development.
- When the Terraform state is empty, the plan should show additions and no changes or destruction.

Example previously observed:

Plan: 51 to add, 0 to change, 0 to destroy.

To save an exact plan:

terraform plan -out=tfplan

Review it:

terraform show tfplan

PART 5 - TEST THE SIGMET POLLER
===============================

Disable the AWS CLI pager for the current PowerShell session:

$env:AWS_PAGER = ""

Invoke the SIGMET poller manually:

  --region us-west-1 `
  --function-name $(terraform output -raw sigmet_poller_function_name) `

PART 6 - VERIFY THE SIGMET S3 ARCHIVE
=====================================

List raw SIGMET objects:

aws s3 ls `
  "s3://$(terraform output -raw sigmet_archive_bucket_name)/raw/source=sigmet/" `
  --recursive `
  --region us-west-1

Expected:

At least one .json.gz object under a key similar to:

raw/source=sigmet/year=YYYY/month=MM/day=DD/hour=HH/sigmet-<poll-id>.json.gz

The object must be in the SIGMET archive bucket, not the aircraft archive bucket.


PART 7 - VERIFY THE SIGMET PROCESSOR
====================================

Wait for asynchronous Kinesis processing.

The poller Lambda invocation can finish before the SIGMET processor runs.

Check processor logs:

aws logs tail `
  "/aws/lambda/$(terraform output -raw sigmet_processor_lambda_name)" `
  --region us-west-1 `
  --since 10m

To wait for new logs:

aws logs tail `
  "/aws/lambda/$(terraform output -raw sigmet_processor_lambda_name)" `
  --region us-west-1 `
  --since 3m `
  --follow

Important:

The --follow option keeps the command open and waits for future log entries.
Press Ctrl+C to stop it.

A successful first processed batch should contain values similar to:

records_received: 13
records_processed: 13
records_failed: 0
bad_records_written: 0
active_hazards_written: 13
hazard_cells_written: 658
hazard_cells_removed: 0
eventbridge_events_published: 13
new_records: 13
updated_records: 0
unchanged_records: 0
h3_resolution: 4

TROUBLESHOOTING
===============

1. Terraform validate succeeds but plan says Lambda ZIP file is missing
---------------------------------------------------------------------

Cause:

The generated dist ZIP files do not exist.

Fix:

Run from the repository root:

.\scripts\build_sigmet_poller.ps1
.\scripts\build_sigmet_processor.ps1
.\scripts\build_metar_poller.ps1


2. Terraform shows duplicate SIGMET or METAR resources
------------------------------------------------------

Cause:

Weather resources still exist in modules/aircraft_foundation.

Check:

Get-ChildItem modules\aircraft_foundation -Filter *.tf |
  Select-String -Pattern "sigmet|metar|taf|weather.changed|active_hazards|hazard_cells"

Expected:

No output.


3. SIGMET poller succeeds but DynamoDB is initially empty
---------------------------------------------------------

Cause:

The Kinesis-triggered processor runs asynchronously.

Fix:

Wait and check:

aws logs tail `
  "/aws/lambda/$(terraform output -raw sigmet_processor_lambda_name)" `
  --region us-west-1 `
  --since 10m


4. CloudWatch log command appears stuck
---------------------------------------

Cause:

The command uses --follow and is waiting for future events.

Fix:

Press Ctrl+C.


5. SIGMET records are in Kinesis but the processor is not running
-----------------------------------------------------------------

Check the event-source mapping:

aws lambda list-event-source-mappings `
  --region us-west-1 `
  --function-name $(terraform output -raw sigmet_processor_lambda_name) `
  --output table

Expected:

State: Enabled
LastProcessingResult: OK


6. MetarLatest is empty
-----------------------

This is currently expected.

The implemented METAR pipeline ends at:

NOAA API
-> METAR poller
-> METAR S3 archive
-> metar-raw Kinesis

A METAR processor has not yet been implemented.


7. Bad records are not visible
------------------------------

No output from the bad-record S3 listing means no bad records were written.

Command:

aws s3 ls `
  "s3://$(terraform output -raw sigmet_archive_bucket_name)/bad-records/" `
  --recursive `
  --region us-west-1
